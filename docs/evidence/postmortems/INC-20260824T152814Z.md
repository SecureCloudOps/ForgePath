# Postmortem: INC-20260824T152814Z defective canary release

## Executive summary

A controlled defective canary returned 1,606 HTTP 503 responses among 32,120
synthetic requests. The stable Service remained on the healthy ReplicaSet. The
incident was detected in 270.265 seconds, acknowledged in 8.543 seconds, and
restored in 374.620 seconds. The canary never exceeded 5% exposure.

## Impact

The controlled failure affected only synthetic canary traffic in the disposable
exercise. Stable traffic remained on the healthy ReplicaSet.

- Affected service: `secure-fastapi-service`
- Availability objective: 99.900%
- Failed synthetic requests: 1,606 of 32,120
- Observed synthetic availability: 95.000%
- Availability error budget consumed: 100.000% of the 1-hour demo budget
- Maximum canary exposure: 5% (1/20 replicas)
- Severity: SEV-2 exercise

## Detection

Prometheus observed `ForgePathSLOFastBurn` firing at 49.96353026987597x burn
before AnalysisRun
`secure-fastapi-service-secure-fastapi-service-6474858754-2-1` completed.

## Root cause

Defective Git revision `570f888919885c84f4767ed80b2d9d21ba2ecf60`
enabled `failureFixture.enabled` and routed the canary test endpoint to an
intentional HTTP 503 response. Candidate logs, pod configuration, the Git diff,
Prometheus metrics, and the failed AnalysisRun independently confirm the causal
chain. Healthy revision `279f7d7dd6ecf8debd9a371284d7d4768f719fac`
remained selected by the stable Service.

## Contributing factors

- The demo profile intentionally compresses alert and error-budget windows for
  an operational exercise.
- Replica weighting requires the synthetic generator to preserve the explicit
  95/5 stable/canary request mix.
- The canary stays probe-healthy, so SLO telemetry—not readiness—must identify
  the defect.

## Recovery

After evidence collection and human authorization, Git revert revision
`834ba5fef90d394c02de853f28d4c8bd681db4ad` restored the healthy desired
state. Argo CD reconciled that revision to `Synced/Healthy`; no imperative
Rollout promotion or workload patch was used. The final Rollout was `Healthy`
with 20/20 ready replicas on stable hash `5c46bc7978`.

- Rollback control: human-approved
- Recovery actor/approver record: `User-approved via Codex`
